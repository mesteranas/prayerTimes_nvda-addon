Prayer Times

Islamic prayer times for a selected location. This document covers development version 2.1.0-dev3.

Shortcuts

  • NVDA+Alt+P: today's times in a readable, read-only text dialog, including date, coordinate time zone and actual calculation method.
  • NVDA+Shift+P: the next prayer, excluding sunrise. Tomorrow's actual schedule is used after Isha.
  • Escape or Close: dismiss the dialog. Use arrow keys to read lines and select/copy text normally.

Customize these shortcuts in NVDA's Input Gestures dialog.

Location

Open the prayer times category in NVDA Settings. Automatic detection uses your public IP address, not GPS; VPNs and mobile networks may produce an incorrect city. Disable it to enter latitude (-90 to 90) and longitude (-180 to 180). Decimal dots and commas are accepted; blanks and invalid values are rejected.

Calculation settings

The settings panel shows the approximate detected city, region, country and coordinates. Use Refresh automatic location to check again. Prayer results identify the location actually used. To correct it, enter a city, district or postal code, for example Ankara, TR or Paris, France, and activate Search for a location. A two-letter suffix after the last comma is a country code; use full region names. Choose a match by its country, region and coordinates, then activate Use selected location. Automatic detection is switched off. Apply or OK saves the choice; Cancel keeps the previous settings. No match is selected automatically. Changing coordinates removes a stale place name.

Search uses Open-Meteo and GeoNames data (CC BY 4.0). Your search and public IP are visible to the service only when you activate Search; its free endpoint is for non-commercial use and has usage limits. Unavailable places can still be entered as coordinates. A place match is not a GPS fix or a guarantee of official timetable agreement.

Choose the method recommended by your local prayer authority. All 23 named Aladhan methods are selectable. Standard/Hanafi Asr and three high-latitude adjustments are available. New configurations start with Automatic, which uses the service's geographically nearest method, not necessarily your local official method. The actual method appears in the result. V2.0 upgrades retain method 5 (Egyptian).

Diyanet (13) and Dubai (16) are experimental Aladhan methods. Diyanet mode does not download the official Diyanet timetable; minute differences can remain. Unavailable polar-day/night results generate a clear error instead of invented times.

The 24-hour option is enabled by default. Disabling it selects 12-hour display without changing calculations. Times and the next-prayer decision use the coordinate time zone, including daylight-saving changes, even if the computer is in another zone. Isha after midnight can belong to the previous calculation day.

Cache and network

Schedules are cached in memory by date, coordinates and calculation settings. The date is rechecked on each command. The next-prayer command obtains tomorrow when needed and, before Fajr, the previous day. IP location expires after one hour. Save/Apply settings or restart NVDA to clear caches immediately. Repeated commands share one active worker; requests have timeouts.

Prayer times use Aladhan over HTTPS, sending selected coordinates and calculation settings. Automatic location uses IPWHOIS.IO / ipwho.is, which sees your public IP. Manual mode does not query that provider. External service availability and free-use limits apply. No extra Python installation is required for packaged time zone support.
